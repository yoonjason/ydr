2026-04-20~21 세션 종료 시점 상황. 코드는 한 커밋 됐지만 **푸시는 안 했고**, 그 이후 데이터 매핑 버그가 드러남.

**Why:** Phase 5α 의 마지막 슬라이스인 '랭커 데이터 인게임 가이드 연결' 까지 코드 작업은 끝냈으나, 인게임 검증에서 보스 이름이 다른 던전의 보스로 표시되는 치명 버그 발견. 푸시 전에 수정해야 함.

**커밋 상태:**
- `5455d53 추가: Phase 5α — 랭커 데이터 활용 인프라 + 안정화 종합` (로컬에만 있음, origin 푸시 안 함)
- 작업 트리에는 `.claude/agents.json`, `.claude/memory/MEMORY.md`, `open-workspace.sh` + 새 메모리 파일 3개가 미커밋 상태

**현재 발견된 핵심 버그 (다음 세션 1순위):**
- `HGPT_RankerData.lua` 의 `_name` 필드가 잘못된 보스 이름으로 채워짐
- 예: `dungeonName = "알게타르 대학"` entry 의 `[2562]/[2563]/[2564]/[2565]` 에 `_name = "동면자 오로스토르 / 스몰데론 / 옹이뿌리 / 화염의 선견자 틴드랄 세이지스위프트"` (이건 에메랄드 꿈의 위안 레이드 보스들)
- 원인: ios-engineer 의 `RankerNameResolver` 가 WCL encID 를 그대로 Blizzard `/data/wow/journal-encounter/{id}` 에 넣음. M+ 던전은 WCL 자체 ID 체계라 Blizzard EJ ID 와 ID 공간 불일치. raid expert 가 처음 보고서에서 경고했던 케이스가 실제로 터짐
- API 자체는 정상. 단지 ID 공간이 안 맞음

**How to apply (다음 세션 작업 순서):**
1. **던전 보스 이름 조회용 Blizzard API 엔드포인트 조사** (사용자 요청) — wow-raid-encounter-expert 에 위임. 후보 조사 항목은 아래 별도 섹션 참조
2. 1번이 안 통하면 **WCL 응답의 encounter name 을 직접 사용** (`characterRankings` / `encounter` 쿼리 응답에 name 필드 포함). 이게 가장 안전. ios-engineer 에 위임
3. 수정 후 잘못 박힌 entries 모두 재수집 (사용자가 맥앱에서)
4. 인게임 `/reload` 후 보스 이름이 정확한지 검증
5. 모두 통과하면 두 번째 커밋 (.claude 환경 + 메모리) + 푸시

**후보 조사 항목 (Step 1 위임 시 wow-raid-encounter-expert 에 전달할 질문 목록):**

A. **던전 단위 엔드포인트**
- `/data/wow/journal-instance/{instanceID}?namespace=static-ko_KR` — 응답에 `encounters[]` 배열이 있는지, 그 항목의 id 와 name 을 사용하면 던전 보스 이름이 정확히 나오는지
- `/data/wow/journal-instance/index` — 활성 던전 목록 조회 가능 여부
- WCL 의 `dungeonID`(예: 12805 = 윈드러너 첨탑) → Blizzard `journal-instance` ID 매핑 구할 수 있는지

B. **M+ 전용 엔드포인트**
- `/data/wow/mythic-keystone-dungeon/index` — M+ 풀 던전 목록
- `/data/wow/mythic-keystone-dungeon/{id}` — 응답에 보스 정보 포함 여부
- `/data/wow/mythic-keystone/affix/index` 등 키스톤 메타데이터 활용 가능성

C. **WCL 응답 활용 (가장 견고)**
- WCL GraphQL `worldData.encounter(id: encID) { name }` 으로 ID → name 직접 조회 가능 여부
- 현재 `RankerNameResolver` 의 enrich 흐름에서 `characterRankings` 응답에 이미 보스 name 필드가 있는지 확인. 있으면 Blizzard API 호출 자체 불필요
- WCL `worldData.zone(id:).encounters[].name` 으로 던전 zone 단위 일괄 수집 가능성

D. **ID 공간 호환성 정리**
- WCL encID ↔ Blizzard journal-encounter ID ↔ ENCOUNTER_START 이벤트 ID 의 3중 매핑 표
- 어느 케이스에서 일치/불일치 하는지 던전/레이드/M+ 별로 (raid expert 가 1차 보고서에서 이미 일부 답변)
- 일치하지 않을 때 어떤 ID 가 EJ_GetEncounterInfo (인게임 API) 와 매칭되는지 — 애드온 측 GetEncounterName 의 EJ 폴백이 정상 동작하려면 알아야 함

E. **검증 데이터셋**
- 현재 잘못 박힌 entries: 알게타르 대학 (2562~2565), 삼두정의 권좌 (2065~2068), 사론의 구덩이 (2000~2001), 하늘탑, 마법학자의 정원, 마이사라 동굴, 공결탑 제나스, 윈드러너 첨탑
- 각 던전의 정확한 보스 이름과 encID 매핑을 검증 기준으로 사용

**우선순위:** C (WCL 응답 활용) 가 가장 빠르고 견고. A, B 는 보조 옵션. D 는 EJ 폴백 정확도 보강용.
